AI-generated look (slop) audit
====================================

This file tracks the "AI-generated" patterns identified in the codebase that make the UI look like generic AI slop.

### 1. UI Patterns (The "Slop" Aesthetics)
- **Excessive Decorations:** The project relies heavily on `SlashMarks`, `Squiggle`, and `UnderlineSwoosh` (found in `components/decorations.tsx`). These are "decorative sugar" frequently used in AI-generated landing pages to hide lack of actual design substance.
- **Sparkle Overload:** The `<Sparkle />` component is used indiscriminately across multiple screens (`app/welcome/page.tsx`, `app/home/page.tsx`, etc.). This is a common trope in "AI app" templates to convey "magic" or "automation."
- **Rounded Containers:** The use of extreme rounding (e.g., `rounded-[42px]`, `rounded-[22px]`) on containers creates a "bubbly" aesthetic common in generic SaaS templates.
- **Icon Tiles:** The `IconTile` component and `activityIcons` mapping create a repetitive, templated look for data visualization.

### 2. Copy/Text ("AI Tone")
- **Generic Taglines:** "Less work. More you." (in `app/page.tsx`) and "Turn comments and DMs into real conversations" (in `app/welcome/page.tsx`) are textbook AI-generated marketing copy—vague, punchy, but devoid of specific value proposition.
- **Automation Names:** "Send Guide on Comment" and "Welcome New Followers" in `lib/data.ts` are overly literal, functional descriptions typical of LLM-generated feature lists.
- **Stat Labels:** The analytics dashboard (`app/analytics/page.tsx`) uses generic metrics like "Avg. Response Time" and "Response Rate" with fake-looking percentage increases, which often come from AI-prompted mockups.

### 3. Structural "Template" feel
- **Hard-coded mock data:** `lib/data.ts` is structured exactly like a standard "AI code generator" output: a large object with specific, rigid types (`Automation`, `Lead`, `Conversation`) that are all pre-populated with "clean" but fake examples.
- **Component nesting:** The `ScreenShell` + `ScreenHeader` pattern in `components/app/shell.tsx` is clean, but the way it's used across every screen indicates a template-driven construction rather than a custom-engineered UI.

### Recommendations for improvement
1. **Remove the flourish:** Delete the `SlashMarks` and `UnderlineSwoosh` components. Replace them with standard typography-based layout (headings, spacing).
2. **Rationalize iconography:** Instead of the generic "sparkle" icon, use iconography that relates to the specific functionality of the section.
3. **Rewrite copy:** Replace the generic "More you" style copy with specific, punchy, human-written descriptions of what the automations actually do.
4. **Humanize the data:** Replace the "perfect" looking mock data in `lib/data.ts` with more varied or representative examples that don't look like they were generated by an LLM prompt.
